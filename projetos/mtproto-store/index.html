MTProto Store

O Telegram como armazenamento de objetos ilimitado e fragmentado, sobre o protocolo nativo MTProto, num único binário de linha de comando autossuficiente.

Go MTProto AGPL-3.0-or-later CLI Cross-platform
Ver no GitHub Releases

O que faz

Sem Python, sem API de bot, sem runtime externo: um único binário estático em Go que faz login numa conta de usuário do Telegram por MTProto e guarda arquivos arbitrários como uploads fragmentados num canal privado.

  • Faz login numa conta de usuário do Telegram (telefone → código → senha 2FA opcional), emulando o cliente oficial Telegram Desktop, o que mantém as sessões estáveis e evita conflitos de logout com outros clientes.
  • Guarda arquivos como uploads fragmentados (chunks), contornando o limite dos bots: até 2 GB por arquivo, ou 4 GB com o Telegram Premium.
  • Cria ou reutiliza seu próprio canal de armazenamento privado, marcado com um sufixo configurável para tocar só nos seus próprios canais.
  • Transmite os downloads de volta, lista os itens armazenados e imprime JSON legível por máquina no stdout, fácil de automatizar.

Construído sobre gotd/td (MTProto puro em Go).

Uso

Todo comando imprime um único objeto JSON no stdout ("ok": true | false).

bash 
$ mtproto-store send-code --phone +55...      # Telegram envia o código
$ mtproto-store sign-in --phone +55... --code 12345 [--password 2fa]
$ mtproto-store init-storage --title "Backups"  # cria o canal privado
$ mtproto-store upload --dir ./fotos            # envia em chunks
{"ok": true}
  • send-code --phone <number>: inicia o login; o Telegram envia o código.
  • sign-in --phone <number> --code <code> [--password <2fa>]: conclui o login.
  • check-auth (alias status): informa o estado de autenticação.
  • init-storage [--title <title>]: cria ou reutiliza o canal de armazenamento privado.
  • upload --dir <path> [flags]: envia os arquivos de um diretório em chunks.
  • download [flags]: baixa um arquivo armazenado.
  • list-remote (alias list-backups): lista os itens armazenados.
  • logout: descarta a sessão local.

Compilação

Compilação cruzada estática para qualquer alvo, sem CGO. Os mesmos binários Linux estáticos rodam no Android (arm64-v8a, armeabi-v7a, x86_64, x86).

CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o mtproto-store .

# alvo específico (ex.: Android arm64)
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o mtproto-store .
Tamanho do binário (uma arquitetura): go build padrão cerca de 23 MB; com -s -w -trimpath cerca de 16 MB; depois upx --best --lzma cerca de 5 a 6 MB. A CI publica binários de release comprimidos com UPX (autodescompacta na inicialização, sobrecarga desprezível); a versão -s -w sem compressão é a alternativa para quem prefere não distribuir binários empacotados.

Configuração

Por variáveis de ambiente:

  • MTPROTO_STORE_STATE (padrão $HOME/.mtproto-store): diretório de estado (sessão, destino, logs).
  • MTPROTO_STORE_TAG (padrão MTPS): sufixo que marca os canais desta ferramenta.
  • MTPROTO_STORE_API_ID e MTPROTO_STORE_API_HASH: seu próprio par de my.telegram.org (o padrão emula o Telegram Desktop).
Termos de Serviço: os padrões internos emulam o cliente oficial Telegram Desktop. Para suas próprias implantações, obtenha e defina seu próprio api_id / api_hash em my.telegram.org e revise os Termos do Telegram. Você é responsável pelo uso que faz da sua conta.

A sessão é uma credencial sensível

Quem conseguir ler a sessão autenticada controla a conta, sem senha nem 2FA. A ferramenta cria o diretório de estado como 0700 e grava a sessão como 0600, mas a proteção real está em onde você aponta MTPROTO_STORE_STATE. Mantenha em armazenamento privado.

No Android, prefira o armazenamento Credential-Encrypted (por exemplo /data/misc_ce/<user>), que só é desbloqueado depois que o usuário se autentica, ao Device-Encrypted (por exemplo /data/adb), legível antes do primeiro desbloqueio.
